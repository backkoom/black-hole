# 使用指南 · 换 HTTPS 证书 & 把备份放到另一块盘

> 这两件事都**不需要改代码**，也不需要重启应用（换证书只需 reload nginx）。
> 两处都能在 **设置 → 系统管理 → 系统设置** 里看到当前状态。

---

## 一、把自签证书换成正式证书

### 0. 先弄清楚现状

打开 **设置 → 系统管理 → 系统设置**，看「HTTPS 证书」面板：

- **主题 / 颁发者**：自签的话两者一样，通常是 `CN=192.168.x.x` 或 `CN=workbench`
- **剩余 N 天**：剩不到 30 天会标成橙色；**已过期会显示负数并标红**
- **SAN**：浏览器校验的是这里，不是 CN。用 IP 访问就必须有 `IP Address:x.x.x.x`

> 自签证书浏览器会提示「不安全」，内网验收可以点「继续访问」；**正式使用建议换成使用方 CA 签发的证书**。

### 1. 准备三个文件

| 文件 | 说明 |
|---|---|
| `your.crt` | 服务器证书（**含中间证书的完整链**最好，避免部分客户端链不完整） |
| `your.key` | 私钥，**不要外传**，也不要提交到仓库 |
| `ca.crt`（可选） | 根证书，只给客户端装，服务器不需要 |

自签的可以用仓库自带脚本生成（内网过渡用）：

```bash
sudo bash deploy/gen-selfsigned-cert.sh 192.168.102.102     # 参数是 IP 或域名
```

### 2. 放到服务器并设权限

Nginx 配置里的默认路径是 `/etc/nginx/ssl/blackhole.{crt,key}`（见 `deploy/nginx-https.conf`）。

```bash
# 先备份旧的，出问题能立刻换回来
sudo cp /etc/nginx/ssl/blackhole.crt /etc/nginx/ssl/blackhole.crt.bak
sudo cp /etc/nginx/ssl/blackhole.key /etc/nginx/ssl/blackhole.key.bak

# 放入新证书（文件名保持一致就不用改配置）
sudo install -m 644 your.crt /etc/nginx/ssl/blackhole.crt
sudo install -m 600 your.key /etc/nginx/ssl/blackhole.key
```

**权限有讲究，弄错会出两种问题：**

| 对象 | 权限 | 错了会怎样 |
|---|---|---|
| `/etc/nginx/ssl` 目录 | `755` | 设成 700 时，nginx 以 root 跑没事，但**应用读不到证书**，系统设置页会显示「没有读到证书」 |
| `.crt` | `644` | 600 时同上（证书本身是公开信息，没必要藏） |
| `.key` | `600` | 放宽会被安全扫描判高危；nginx 以 root 读没问题 |

### 3. 校验再生效

```bash
# ① 看证书本身对不对（主题、有效期、SAN）
sudo openssl x509 -in /etc/nginx/ssl/blackhole.crt -noout -subject -dates -ext subjectAltName

# ② 看 nginx 配置有没有语法错
sudo nginx -t

# ③ 生效（reload 不断连接，比 restart 安全）
sudo systemctl reload nginx

# ④ 从外部验一次
curl -sI https://你的域名或IP/ | head -3
echo | openssl s_client -connect 你的域名或IP:443 -servername 你的域名 2>/dev/null | openssl x509 -noout -subject -dates
```

### 4. 验收清单

- [ ] 浏览器地址栏是锁形图标，点开显示新证书的颁发者
- [ ] **设置 → 系统设置 → HTTPS 证书**：主题/颁发者/有效期都变了，剩余天数变多
- [ ] 页面没有「混合内容」警告（浏览器控制台 Console 里搜 `http://`）
- [ ] 登录、上传文件、下载文件都正常（证书换了不影响 Cookie，但建议重新登录一次）

### 5. 出问题怎么退回去

```bash
sudo cp /etc/nginx/ssl/blackhole.crt.bak /etc/nginx/ssl/blackhole.crt
sudo cp /etc/nginx/ssl/blackhole.key.bak /etc/nginx/ssl/blackhole.key
sudo nginx -t && sudo systemctl reload nginx
```

> 换的是**域名**的话，还要改两处：nginx 里的 `server_name`，以及 `/etc/blackhole/api.env` 的
> `APP_ORIGIN=https://新域名`，然后 `systemctl restart blackhole-api@3001 blackhole-api@3002`。
> ⚠️ 不重启的话，Cookie 的来源校验会对不上，写操作全 403。

### 6. 关于 HSTS

自签阶段**故意没开** HSTS：一旦浏览器记住“这个站只走 https”，以后临时退回 http 会很麻烦。
**换成正式证书之后**，可以到 `deploy/nginx-https.conf` 里把 HSTS 那行取消注释再 reload。

## 二、把备份放到另一块盘 / NAS

### 为什么必须做

默认备份目录 `/data/backups/blackhole` 和数据库在**同一块盘**上。盘挂了，库和备份一起没——
这等于没有备份。真正的备份要在**另一块物理设备**上。

### 1. 挂载目标盘（NAS 或第二块盘）

以 NFS 为例（CIFS/SMB 同理，换 `-t cifs` 和参数）：

```bash
# ① 建挂载点
sudo mkdir -p /mnt/backup

# ② 临时挂一次，确认能通
sudo mount -t nfs 192.168.102.200:/volume1/backup /mnt/backup

# ③ 能写才算通
sudo touch /mnt/backup/.probe && sudo rm /mnt/backup/.probe && echo OK

# ④ 写进 /etc/fstab，重启也在（示例）
# 192.168.102.200:/volume1/backup  /mnt/backup  nfs  defaults,_netdev  0 0
```

> ⚠️ **最常见的坑**：盘没挂上就开始备份。脚本会**静默写到本地盘**，看起来“备份成功”，
> 其实那份备份还在同一块盘上。每次改完路径都要 `df -h /mnt/backup` 确认一下。

### 2. 在界面里改路径

**设置 → 系统管理 → 系统设置 → 备份**：

| 字段 | 填什么 |
|---|---|
| 备份目录 | `/mnt/backup/blackhole`（绝对路径，必须已挂载） |
| 保留份数 | 14（每天一次 ≈ 两周） |
| 启用定时备份 | 开 |

点「保存」——**不用重启**。配置存在数据库里，备份脚本下次运行时会自己读。

> 也可以不改界面，直接改 `/etc/blackhole/api.env` 的 `BACKUP_DIR`。
> 优先级：**命令行参数 > 界面设置（数据库）> 环境变量**。所以界面上一旦设过，就以界面为准；
> 想清掉界面设置：`DELETE FROM system_setting WHERE key LIKE 'backup.%';`

### 3. 立刻验一次（别等半夜）

```bash
# 手动跑一次
sudo bash /data/blackhole/deploy/backup.sh

# 看它落在哪、有几份
ls -1 /mnt/backup/blackhole | tail -5
sudo cat /mnt/backup/blackhole/<最新时间戳>/manifest.txt | head -20
```

`manifest.txt` 里应该有：备份时间、主机、版本、数据库 SHA256、**各表行数**、文件实体大小。
行数为 0 或文件很小，说明那次备份是空的，别当成功。

### 4. 验收清单

- [ ] `df -h /mnt/backup` 显示的是网络盘/另一块盘，不是 `/data`
- [ ] 手动跑一次备份，`manifest.txt` 里 `app_user`、`task`、`project` 行数都对得上
- [ ] **做一次恢复演练**（重要：没演练过的备份等于没有）：
      `sudo bash deploy/restore.sh --dump <备份目录> --to workbench_drill`
      跑完核对行数一致，再 `DROP DATABASE workbench_drill`
- [ ] 设置页「备份」面板里的目录和实际一致

### 5. 出问题怎么退回

备份目录改错/盘掉了，脚本会在 `set -e` 下直接失败（定时任务会报红，不会悄悄成功）。
在设置页把目录改回 `/data/backups/blackhole` 并保存即可，或者临时把「启用定时备份」关掉。

## 三、这两件事在系统设置页里的位置

```
设置 → 系统管理 → 系统设置
├─ 备份           目录 / 保留份数 / 启用定时   ← 可改（仅超级管理员）
├─ 文件存储       目录 / 单文件上限 / 已用容量  ← 只读（改要动环境变量并重启）
├─ HTTPS 证书     主题 / 颁发者 / 有效期 / 剩余天数 / SAN  ← 只读
└─ 版本           构建时间 / Node 版本
```

> 普通管理员能看到这一页，但**保存按钮是灰的**——备份目录决定服务器往哪写盘，只有超级管理员能改。
