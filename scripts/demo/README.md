# 演示数据（DEMO）

> ⚠️ 这里灌入的是**演示数据**，不是真实业务数据。删光不影响系统运行。

## seed-month.sql —— 一个月量的业务演示数据

| 项 | 内容 |
|---|---|
| 时间跨度 | 2026-10-20 ~ 2026-12-10（重点压在最近一个月） |
| 项目 | 4 个：2026 年度信息化建设 / MES 二期推广 / 网络安全加固专项 / 数据中台试点 |
| 里程碑 | 8 个（每项目 2 个，甘特图菱形） |
| 任务 | 31 条：周计划/月度父任务 10 条 + 日常子任务 21 条（parentId 串成层级） |
| 状态分布 | 已完成 9 / 进行中 8 / 待处理 14，其中 4 条故意做成逾期 |
| 风险 | 6 条（高 3 / 中 2 / 低 1，含 open / handling / resolved） |
| 随记 | 8 条（11-04 ~ 11-18） |
| 会议 | 6 场（4 场过去 / 2 场今天 / 1 场未来） |

**幂等**：脚本开头会先 DELETE 掉 task / milestone / risk / meeting / idea / project 的全部数据，再重建。

```bash
PGPASSWORD=*** psql -h 127.0.0.1 -U blackhole -d blackhole_test -f scripts/demo/seed-month.sql
```

## 怎么识别这些演示数据

- **项目名**：只认这 4 个名字（见上表），真实项目不会用这些名字
- **任务标题**：都是制造业信息化场景（MES 联调、等保整改、预算编制…）
- **风险编号**：带项目前缀，如 `MES-01`、`SEC-02`、`DAT-01`、`ANN-02`

## 与 db/seed.ts 的区别（别混）

| 脚本 | 作用 | 删了会怎样 |
|---|---|---|
| `db/seed.ts` | **基础数据**：组织架构 6 级 + 8 个账号 + 工作台布局模板 | ✗ 系统登不进去 |
| `scripts/demo/seed-month.sql` | **业务演示数据**：项目/任务/风险/会议 | ✓ 只是页面变空 |
